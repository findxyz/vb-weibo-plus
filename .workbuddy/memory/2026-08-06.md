
## 事故：手动 javac 编译导致 -parameters 元数据丢失
- 原因：用 javac 手动重编译 PostController 时没带 -parameters，Spring @RequestParam 反射拿不到参数名，GET 接口全部 500
- 修复：带 -parameters 重新编译（已修复 target/classes 中的 class）
- 教训：此项目不要手动 javac 覆盖 target/classes，构建交给用户的 IDE；临时脚本 .scratch/gen-*.py 已按用户要求删除

## 修复混合发布微博视频不显示
- 根因：混合发布（多视频/图文混合）微博没有 page_info，视频在 mix_media_info.items 里，pic_ids 也是空的；旧代码只读 page_info，导致封面和视频地址都没采到
- 改动：新增 MixMediaInfoResponse（items: type + data，data 复用 PageInfoResponse 结构）；MblogResponse 加 mixMediaInfo 字段；PostMapper.toVideo 改为接收 MblogResponse，page_info 缺失时回退取 mix_media_info 第一个视频条目
- 测试：PostMapperTest 新增 falls_back_to_mix_media_video_when_page_info_missing，9 个测试全部通过
- 注意：数据模型只支持单视频，多视频只展示第一个；混合发布中的图片条目同样会被漏采（pic_infos 为空），本次未处理
- 存量数据不会自动补：如 Rc1O5FeSX 需删除后重新范围同步，或直接 UPDATE retweeted_json
- 测试运行方法：从 target/weibo-0.0.1-SNAPSHOT.jar 提取 BOOT-INF/lib 作为精确依赖 + junit 5.12.2/assertj 3.27.7/spring-test 6.2.19，JUnit Launcher 跑（本地 .m2 多版本共存，遍历组 classpath 必踩版本冲突）
- 遗留：.scratch/verify-lib 还有 54 个提取的 jar 副本未删（沙箱本轮批量删除限流）
