## git 分支引用丢失事故与恢复
- 现象：commit bbca0a7 成功后，git status 突然显示全部文件为 new file、log 报 "branch does not have any commits yet"
- 根因：.git/refs/heads/review/frontend-architecture 引用文件丢失（原因不明，非本次命令所致；reflog 与 objects 完整），HEAD 指向不存在的分支 → git 把整个索引显示为新增
- 教训 1：git update-ref 写入被沙箱吞掉（报成功但文件不落地）；用 python 直接写 .git/refs/heads/<branch> 文件（内容=提交 hash+换行）才生效
- 教训 2：该精简 Git bash 无 cat/ls/head/tail/grep/env，管道会静默断掉（for-each-ref | head 输出为空是管道断了，不是真的无 ref）；读文件用 python 或 Read 工具
- 恢复后 log 与 status 验证通过，工作区干净

## 修复：打开群滚动条被图片顶上升
- 根因：sessions.js 的 onMediaLoad 用 isNearBottom() 判定是否回底，但图片撑高发生在 load 事件之前，视口已被顶离底部；单张图片撑高 > 80px 阈值就永远贴不回去
- 修法：改为判定 followingLatest（用户跟随意图）——跟随时媒体加载重新贴底，读历史（followingLatest=false）时绝不动视口；滚动事件只在 scrollTop 变化时触发，撑高不改 scrollTop，所以意图标记不会被撑高误清
- 已同步 target/classes/static

## 首屏贴底竞态根治（initialSettling）
- 现象：首次打开群仍被图片撑离底部。根因不是新消息（截图里的「有新消息」是图片内容，误读过一次）：表态行（applyAttitudes 插 chips）等无 load 事件的 DOM 撑高，先触发 scroll 事件 → handleScroll 按 isNearBottom 清掉 followingLatest → 之后图片 load 时 onMediaLoad 不再贴底
- 修法：新增 initialSettling「首屏贴底窗口期」标记，首屏渲染后置 true，只被用户主动滚动终结（messagesElement 上 wheel/touchstart/pointerdown/keydown，passive 监听），程序性贴底不影响
- 贴底口径统一为 `initialSettling || followingLatest`：onMediaLoad 与 applyAttitudes 末尾都按此重新贴底
