# Scroll-to-bottom is a one-shot action, never a persistent mode

The chat message stream has no persistent auto-stick state. Scrolling to the bottom happens only as a one-shot action with three triggers: first entry into a group (including compensation while late-loading media and attitude rows grow the content), the new-messages pill, and the scroll-bottom button. New Group Messages arriving through View Refresh or Catch-up never move the viewport; the Reading Position is held, and new messages are announced for the user to jump to. Leaving a group (page switch or group switch) remembers the Reading Position; re-entry restores it, falling back to first-entry behavior when it cannot be restored.

Chosen because the previous persistent follow mode (a `pinning` flag set on open and on every jump-to-bottom, cleared only by user input) repeatedly broke the case it was meant to serve: the chat and post pages are separate documents, so every page switch re-entered the group, re-engaged follow mode, and threw the reader back to the bottom, destroying the position they were reading. Follow mode also cannot distinguish "the user wants the newest message" from "the user is reading history", so it optimizes for the former every time. One-shot actions with a bounded settle (media growth compensation, ended by user input) keep the convenience of the buttons without claiming the viewport between actions. Re-introducing any persistent follow — on new messages, on re-entry, or on content growth outside a settle — is a regression against this decision.
