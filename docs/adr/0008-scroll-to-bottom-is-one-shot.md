# Scroll-to-bottom is a one-shot action, never a persistent mode

The chat message stream has no persistent auto-stick state. Scrolling to the bottom happens only as a one-shot action when the chat page opens (first open, refresh, or return from another page), when a group is selected from the list, or when the new-messages pill or scroll-bottom button is clicked. Late-loading media and attitude rows are compensated while that action settles. New Group Messages arriving through View Refresh or Catch-up never move the viewport; they are announced for the user to jump to. Opening the chat page always lands at the newest messages, exactly like selecting a group from the list; no position is remembered across page loads.

Chosen because the previous persistent follow mode (a `pinning` flag set on open and on every jump-to-bottom, cleared only by user input) repeatedly broke the case it was meant to serve: the chat and post pages are separate documents, so every page switch re-entered the group, re-engaged follow mode, and threw the reader back to the bottom, destroying the position they were reading. Follow mode also cannot distinguish "the user wants the newest message" from "the user is reading history", so it optimizes for the former every time. One-shot actions with a bounded settle (media growth compensation, ended by user input) keep the convenience of the buttons without claiming the viewport between actions. A later revision remembered a Reading Position when the page was left and restored it on reopen; in practice a stale anchor sent every refresh back-paging through days of history and re-anchoring mid-list, which read as chaotic scrolling, so reopening was made identical to selecting the group from the list. Re-introducing any persistent follow or cross-page position restore — on new messages, on return from another page, or on content growth outside a settle — is a regression against this decision.
