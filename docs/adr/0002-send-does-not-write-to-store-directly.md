# Send does not write to the message store directly

Sending a text message does not insert the sent message into the local message store. The send flow calls Weibo's `send_message.json` and, only on a successful response, triggers one `saveIncremental(gid)` pull so the new message enters the store through the same `query_messages.json` path as every other message. No optimistic local write, no direct insert of the `send_message` response.

Chosen because the project rule is explicit: only data pulled from `query_messages.json` may be written to the store, and `send_message.json` returns `mid`/`time`/`gid` but not the full display fields needed for rendering, so a direct insert would produce a half-rendered message. `saveIncremental`'s first pull (no `max_mid`) fetches the latest batch and naturally covers the newly sent message, so the pull is both the authority and the sufficient source. If the send succeeds but the follow-up sync pull fails, the request fails with `MessageSentButSyncFailedException` (HTTP 409): the message is already on Weibo, the local store is only stale until the next periodic `SyncTask` or manual refresh recovers it, and the UI keeps the composed text so the operator can retry. Reversing to a direct insert would require reconstructing display fields from the send response or a second query, and would violate the pull-only-write invariant.
