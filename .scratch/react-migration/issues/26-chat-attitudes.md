# 26：chat 实时表态

**What to build:** chat 预览增加表态开关：打开后按当前消息批量拉取表态并显示表情条，新消息到达时随批刷新；开关状态持久化，关闭后不再请求但保留已显示内容。

**Blocked by:** 25，已完成。

**Status:** resolved

日期：2026-10-17。用户要求继续下一票。本票只做表态的读取与展示，不实现点击表态或发送表态。

## 实施边界

### 开关与持久化

- 消息区右下角增加表态开关，默认关闭；状态写入 `localStorage` 的 `weibo-chat:attitudes`，刷新后保持。
- 开关带 `aria-pressed` 与说明性 `aria-label`；打开时显示为激活态，关闭时显示斜线。
- 打开时立即为当前可见消息补一次表态；关闭后不再发起表态请求，已显示的条目保留。

### 拉取与展示

- 打开后按批次拉取：首屏、向上翻页、新消息（轮询与 Catch-up）到达时，用该批消息的 `mid` 请求 `GET /chat/attitudes?gid&mids=...`。
- 结果只应用到当前群；同一 `mid` 以最新响应为准，迟到响应不得跨群污染；请求失败静默降级，不影响消息展示。
- 消息下方显示表态条：表情贴图优先（共享映射），缺失时退回近似符号或名称，再显示数量；`selected` 项使用选中样式；数量为 0 或缺失的条目不显示。
- 表态条增删引起的高度变化沿用现有落底收尾与 ResizeObserver 补偿。

## 验收标准

- [x] 默认不请求表态；打开开关后立即请求当前可见消息的 `gid` 与 `mids`，并显示对应表情条。
- [x] 首屏、向上翻页与新消息到达时按批补拉，新消息的表情条在其渲染后出现。
- [x] 关闭开关后不再发起表态请求，已显示的表情条保留。
- [x] 刷新页面后开关状态保持；打开状态会在首屏加载后自动补拉。
- [x] 选中项使用选中样式，数量与名称正确，零数量条目不显示。
- [x] 请求失败不影响消息展示；切群或卸载后旧响应不修改新群。
- [x] 旧正式 chat 与 React post 回归、构建资源检查保持通过。

## 实施与验证证据

日期：2026-10-17。

### 实现

- `MessageList.tsx` 增加表态偏好（`localStorage` 的 `weibo-chat:attitudes`）、按批拉取与写回：首屏、向上翻页、新消息到达时用该批 `mid` 请求；开关打开时立即为当前可见窗口补一次；关闭后不再请求但保留已显示条目。
- `applyAttitudes` 以消息 Map 为准写回消息对象并重建有序列表，空数组同样落盘以清掉旧表态；请求失败只 `console.warn`，不影响消息；组件按群重新挂载并中止旧请求。
- `MessageItem.tsx` 渲染表态条：贴图优先（共享映射）、缺失时退回近似符号或名称，再显示数量；`selected` 使用选中样式；零数量条目过滤。
- `api.ts` 增加 `fetchAttitudes` 与 `Attitude` 类型；Vite 代理补上 `/chat/attitudes`；`chat.css` 增加表态条与开关样式，沿用旧页的 5 列网格、胶囊与开关位置。
- 向上翻页的合并改为以消息 Map 为准，避免表态等异步写入被旧的 `ordered` 快照覆盖。
