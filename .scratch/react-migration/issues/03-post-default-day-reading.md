# 03：React post 默认日期的本地博文阅读

**What to build:** 使用者打开 post 预览后，默认查看全部博主最新有效日期的本地 Blogger Blog。页面呈现博主、日期与博文三个区域，并能阅读作者、时间和清洗后的正文。开发预览与构建后的 JAR 使用同一套查询和显示行为。

**Blocked by:** 02，前端生成资源参与 Maven 测试与 JAR 打包。

**Status:** resolved

## 实施边界

使用现有博主列表、日期聚合和按日列表接口，保持参数、日期时区与错误响应语义。
默认范围是全部博主，使用聚合结果中的最新有效日，不使用机器当前日期代替实际有数据的日期。
本票只实现默认打开的读取路径；显示当前默认范围和日期，其他切换与搜索能力在后续票接入。
正文富文本沿用已有清洗和安全链接语义，保持换行与现有内容格式；清洗失败时使用安全降级。
将查询状态、默认选择和展示组件分开，查询结果通过 props 驱动显示；结果总数沿用服务端语义。
接口失败时提供局部可理解的提示，列表查询保留既有重试能力；不以重复初始化整页代替列表失败恢复。
旧正式 post 保持完整功能，预览明确表示当前只覆盖默认阅读路径。

## Acceptance criteria

- [x] 打开预览默认使用全部博主范围，加载日期聚合并选中最新有效日，发起对应日期的本地列表查询。
- [x] 默认列表沿用既有按日加载的分页参数和日边界，不新增分页 UI、不启动 Background Capture。
- [x] 预览采用 post 纸感皮肤和三栏布局，显示博主名称、当前默认日期、服务端总数及可读博文卡片。
- [x] 作者、时间、正文、换行与已有链接语义可见；正文清洗阻止可执行恶意内容。
- [x] 空博主、无日期、当日无博文和各查询失败均有明确状态；列表重试不会覆盖已成功加载的其他区域。
- [x] 页面卸载和请求失效后，过期响应不继续修改界面；没有重复初始化或无限请求循环。
- [x] 使用既有 HTTP 测试方式覆盖默认读取、日边界、空数据、失败重试和正文清洗；开发预览与生产 JAR 的相关检查通过。
- [x] 旧正式 post 与 chat 的定向回归保持通过，正式入口尚未切换。

## 验证方法

在真实浏览器中使用本地 HTTP 测试替身断言当前范围、日期、查询参数与可见卡片内容。
选择可复现的日期数据，覆盖最新有效日与当天日期不同的情况。
使用已有清洗测试案例验证正文，不只检查清洗函数被调用。
运行前端检查、相关 UI 测试和生产资源冒烟；完整后续 post 功能不属于本票通过条件。

## 范围外

用户切换博主和日期、完整媒体展示、图片查看器、转发完整样式、高级搜索、博主管理、按时段采集 Blogger Blog、扫码流程、定时 View Refresh，以及正式入口切换。
本票完成只代表默认读取路径可用，不能宣布 post 整页迁移完成。

### 最终审查修正

两轴审查指出两项 P3 问题，本票统一修正：博文总数遵循设计规范，使用 12px 与 `tabular-nums`；Vite 开发预览的正式页面链接使用配置的后端地址，生产构建保留同源 `/post/index.html`。Vite 从既有 `API_PROXY_TARGET` 推导一个地址，同时用于 API 代理与显式定义的单个前端变量，不批量暴露环境配置，也不代理旧页面资源。

修正前真实浏览器断言分别发现总数字号为 15px、开发链接仍为相对路径；修正后完整前端 18 项检查与类型检查、构建通过，新增检查实际点击链接到达配置的 HTTP 后端页面。构建后的 Java React 页面检查同时验证生产链接保持相对路径及计数计算样式。父任务在审查基线 `13302f5` 已完成 `mvn clean verify`，431 项测试全部通过；本轮修正只运行相关前端与生成资源检查。
