# 06：React post 已迁移区域视觉对齐

**What to build:** 将已迁移的 post 阅读区域对齐用户现用旧版的纸感外观，保持查询与导航行为。

**Blocked by:** 05，已完成。

**Status:** claimed

日期：2026-10-14。用户已授权本票实施。

## 范围与依据

以运行中的旧 post 页面、仓库旧 post 的 DOM／CSS 和 docs/design/DESIGN.md 为参照。先对照真实浏览器截图与尺寸，再使用相同只读 fixture 比较新旧页面。

恢复 44px 标题栏及微博图标、280px／200px 三栏、48px 面板标题、虚线分栏、纸面背景、微软雅黑标题与导航、三级日期缩进和倾斜荧光笔选中态。预览说明与正式页链接保留在标题栏，删除重复的范围和日期徽块，以按钮选中语义表达当前选择。计数归入面板标题。

恢复博主行及普通博文的 48px 头像列、既有头像和认证标记，直接读取接口已有 avatar／verified 字段。图片地址只接受 HTTP／HTTPS，缺失或加载失败时显示名称首字；不新增头像跳转。复用既有微博 SVG 素材，构建时由 Vite 纳入产物。

卡片对齐 720px 最大宽度、铅笔描边、间距、作者／时间和正文布局，取消旧版不存在的卡片投影。纯转发的无头像布局只在既有 pics／video 字段确认没有外层媒体时应用；媒体本身仍不展示。原文安全清洗及链接默认无下划线、悬停直线保持。

未迁移的搜索行及管理按钮不制造假控件或空白占位。它们造成的局部位置差异属于后续功能范围，不宣称整页像素一致。图片／视频、查看器、来源／地区／互动操作、搜索、管理、采集、登录、正式入口切换与共享工具搬迁均不在本票。

## Acceptance criteria

- [ ] 相同数据下，新旧标题与面板几何、导航字体／缩进／选中态、普通卡片宽度／头像／正文结构一致；在 1280×800 与 1600×900 比较真实浏览器，并检查最小 900×560 布局。
- [ ] 面板标题固定，博主、日期与博文内容各自滚动；键盘选择、焦点环、加载／错误／重试、空状态和日期折叠继续可用；预览与正式页跳转明确。
- [ ] 头像存在／缺失／失败／不安全地址及认证、普通／纯转发／含未迁移外层媒体的布局均有真实浏览器覆盖。查询与正文安全行为保持，无业务写请求及浏览器异常。
- [ ] 前端全套检查、类型检查、双入口构建和 Maven 构建资源检查通过；规范与规格审查通过，更新路线图并保存可回退提交与发布包。

## 验证方式

前端浏览器测试复用本地 HTTP fixture，与旧源码页面对比已迁移区域的计算样式和尺寸，不使用用户数据写接口。新截图人工检查，业务查询继续沿用原测试。Maven 使用独立 worktree 打包，避免占用中的用户 JAR；定向验证 ReactPreviewPageTest，旧页面未修改时不重复其完整套件。
