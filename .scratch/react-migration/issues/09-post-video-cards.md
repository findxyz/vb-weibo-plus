# 09：React post 视频卡片

**What to build:** 展示普通与转发视频封面，以旧版新窗口跳转方式打开视频页。

**Blocked by:** 08，已完成。

**Status:** resolved

日期：2026-10-15。用户确认下一步，开始本票。

## 范围与依据

沿用 PostVideoView 的 coverUrl／pageUrl、旧 posts.js 的 hasPlayableVideo／createPostVideo／外层去重规则、post.css 及 DESIGN.md。页面不增加内嵌播放器、下载或预取视频文件，不引入依赖或后端接口。

普通视频位于正文／图片之后，转发视频位于原文／原文图片之后。只有封面和视频页地址均完整且安全时展示；视频页接受可解析的 HTTP／HTTPS，封面接受同源精确 /post/video-cover 或 HTTP／HTTPS。空字段、null 和非法地址不形成卡片或请求。原始外层媒体仍用于既有纯转发分类，不因封面失败改变作者布局。

内外层均可展示且 pageUrl 字符串相同时，仅保留转发视频，不按封面地址去重；不同视频各显示一份。复用既有 /post/video-cover 读取，Vite 只增加该精确路径的代理，生产继续同源。

封面沿用 320px 宽、最大 240px 高、8px 圆角和居中 48px 圆形播放标识，lazy／async。播放标识使用 DESIGN.md 的纸感硬投影令牌，避免复制旧媒体标识的模糊投影；其余正常布局／颜色／边框与旧版对照。

点击或键盘激活在新窗口打开 pageUrl，noopener 阻断 opener，当前页面、日期及阅读位置保持。图片查看器不接管视频，图片和视频混合时仍能各自工作。

封面失败只隐藏封面，保留可点击的播放占位与可访问名称，不重试或改源。旧 CSS 依赖 img 提供容器尺寸，失败时可能失去点击区域；若浏览器复现，则以独立修复提交保留 320×240 的占位，沿用已有尺寸与皮肤令牌，记录差异，不改旧正式页面。

## Acceptance criteria

- [x] 普通／转发／纯转发视频位置、封面尺寸、播放标识居中与旧版正常路径一致；同视频去重和不同视频并存正确。
- [x] 地址不完整／非法时无卡片或危险请求；封面失败仍能点击／键盘跳转，noopener、当前 URL／日期和图片查看器保持。
- [x] lazy／async、长列表按需封面读取与精确开发代理通过；不加载视频文件或内嵌播放器。
- [x] 前端全套、类型／双入口构建、Maven 资源检查及独立 JAR 视频读取通过；审查、演进地图、提交及发布包证据完整。

## 实施与验证

继续在已确认的浏览器 UI／HTTP fixture 边界逐切片实施。视频页用本地拦截替身，不访问外部网站；正常尺寸与旧页面使用相同封面响应对照。失败占位若需修正，独立提交记录。

独立 worktree 构建并定向运行 ReactPreviewPageTest。独立 JAR 使用隔离 SQLite、缺失 Credential、空采集群号与 loopback 封面服务，读取真实视频封面接口及 retweeted 参数，不请求外部微博媒体。旧正式页面、运行中的 JAR 和后端不切换。
