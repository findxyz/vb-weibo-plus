# 07：React post 普通与转发图片卡片

**What to build:** 展示普通微博及转发原文中的图片，沿用旧版纸感网格、缩略图读取和失败隐藏行为。

**Blocked by:** 06，已完成。

**Status:** claimed

日期：2026-10-14。用户已授权本票细化与实施。

## 范围与旧行为依据

读取现有 PostImageView 与 RetweetView.pics，不新增后端接口、数据库字段或依赖。来源为旧 posts.js 的 createPostPics／createRetweetBlock／createPicEl、post.css 与 DESIGN.md。

普通多图按原顺序显示三列 120px 格子、6px 间距。原始 pics 数量为 1 时使用单图布局，保持图片比例，最大宽高 320px；已知尺寸沿用 thumbnailWidth／thumbnailHeight 优先、originalWidth／originalHeight 回退。转发图片使用三列 100px 格子、4px 间距和既有斜纹底，放在原文之后；单张转发图片仍用 100px 格子。

展示源优先 thumbnailUrl，缺失或不安全时回退到可用 originalUrl。只接受后端生成的同源 /post/image 地址及 HTTP／HTTPS 图片地址；缺失或非法地址不产生格子。缺失或空 pics 不影响文字、计数及纯转发布局；不因重复 pid 丢弃图片或跨内外层去重。原始外层媒体数量仍决定纯转发分类，不因图片加载失败改分类。

图片使用原有替代文本、lazy 与 async。加载失败时隐藏整个格子，不显示破图或追加重试请求；普通／转发正文、其他图片和导航继续可用。本票仅展示图片，不设置图片链接、点击放大、手形光标或假查看器。查看器及视频另票迁移。

开发时仅为 /post/image 增加精确代理，保留原有查询代理和页面／模块资源隔离。发布时继续同源，通过 Maven 产物与独立 JAR 验证真实接口返回的图片地址。

## Acceptance criteria

- [ ] 普通单图／多图和转发图片顺序、缩略图优先、原图回退、尺寸／网格与旧版一致；相同 fixture 比较真实浏览器布局与截图。
- [ ] 空图片／无地址／非法地址无破图；图片失败隐藏格子，其他内容、纯转发分类、博主与日期选择及总数保持正确；原图不会在有缩略图时提前加载。
- [ ] lazy／async、长列表按需读取、独立滚动及开发精确图片代理通过；图片无点击放大或页面跳转，正式页仍可访问。
- [ ] 前端全套浏览器检查、类型／双入口构建、Maven 构建资源检查及独立 JAR 图片冒烟通过；规格／规范审查通过，更新路线图并保存提交和发布包。

## 实施与验证

延续已确认的真实浏览器与 HTTP fixture 测试边界，以普通图片为首个失败测试和最小实现，再接转发、失败、非法地址与滚动。新增小型图片展示组件，共用内外图片单元；不引入查看器状态或额外请求客户端。

新旧页面使用相同本地图片响应，比较三种布局。Maven 在独立 worktree 构建，仅定向运行 ReactPreviewPageTest；旧页面源码不修改。独立 JAR 使用隔离数据库、本地已缓存图片、缺失 Credential、空采集群号及 loopback，验证 API、图片 MIME、两种入口和浏览器读取。避免为了图片测试请求外部微博源。
