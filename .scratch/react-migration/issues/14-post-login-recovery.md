# 14：React post 登录状态与扫码恢复

**What to build:** 迁移登录检测、401 失效提示及内嵌扫码恢复，保持本地阅读可用。

**Blocked by:** 13，已完成。

**Status:** claimed

日期：2026-10-17。用户授权连续完成至任务 16。

依据 shared/login.js、qr-login.js、ADR-0007、WeiboLoginController 和 PostPageTest。页面启动只 GET /weibo/login/status 一次，cache=no-store；仅 valid 严格为 true 代表有效，形态异常为失效。检测失败不打扰阅读，不轮询状态。博主、日历、正文、搜索接口 401 展示统一失效区域；搜索 401 关闭弹窗，保留主阅读选择及左栏过滤，401 不重复展示普通错误。

仅显式点击扫码按钮才 POST /weibo/login/qr，最长等待 360 秒，不自动重试、不提供取消。等待时按钮禁用／“扫码中…”，3 秒首拉二维码、此后从开始时每 10 秒刷新 /weibo/login/qr/image?t=，成功预加载后替换图片；失败保留最后可用二维码，首图失败提示重试。结束停止轮询，失败恢复按钮并显示扫码失败，没图显示“暂无二维码”；成功清除图片／提示并重新检测状态。组件卸载清理请求、定时器和预加载回调，不声称取消服务端扫码。

恢复后仅重试当前仍为 401 的活动阅读查询，不重置范围／日期，不重发搜索或业务写请求。该恢复补齐避免扫码成功后仍停在失败阅读。后续管理与采集票复用这一失效入口。

样式沿用旧纸感登录区，二维码／加载位 180px、4px 圆角、纸色与朱砂焦点；900×560 可用，列表独立滚动。Vite 仅补齐上述三个精确代理，既有生产同源路径不变。

- [ ] 显式单次 POST、防重入、360 秒超时、成功复查与仅失败阅读恢复通过。
- [ ] 首图／刷新节奏、失败保留、结束／卸载清理与再次扫码隔离通过。
- [ ] 纸感布局／键盘、前端回归／构建、Maven 资源、本地替身 JAR 与独立审查通过。
