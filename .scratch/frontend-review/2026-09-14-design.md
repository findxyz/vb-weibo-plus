# 前端审查三批优化 · 设计方案

日期：2026-09-14　前置：2026-09-14 全量审查报告（chat + post 共 21 个前端文件），历史轮次见 `2026-09-12-round2.md` / `2026-09-12-round3.md`

## 全局假设（先声明，可推翻）

- A1：后端把 `start` / `end` 查询参数按 Asia/Shanghai 解释，`/post/calendar` 的日期分组同为上海时区。批次二据此把 post 页统一到上海时区；若后端实为按请求方时区解释，则方案改为「全链路浏览器本地时区」，改动面不变。
- A2：不做构建工具、不引框架，保持原生 ES Modules + 静态资源现状。
- A3：仓库无前端自动化测试设施，各批验证以「手动走查清单 + DevTools + curl」为准；有 Java 侧改动处补 JUnit。

## 批次一：可访问性快赢（纯前端，零接口变更，预计 6 处小改）

### 1.1 aria-live 策略重构 + shared announcer

问题：`aria-live="polite"` 挂在高频更新的大容器上（chat/index.html 的 `#messages`、`#groups-list`；post/index.html 的 `#bloggers-list`、`#dates-list`、`#posts`），3 秒轮询下屏幕阅读器持续被打断。

设计：

- 新增 `shared/announcer.js`：导出 `createAnnouncer()`，懒创建一个 visually-hidden、`role="status"`、`aria-live="polite"` 的 div 挂到 `document.body`，返回 `announce(text)`；相同文案 1 秒内去重，写入前先清空再写（保证相同内容也能触发朗读）。
- HTML：移除上述 5 个容器的 `aria-live`（容器不再自带 live region）；小状态行（`role="status"` 的 `#groups-state` 等）保留，它们本就低频。
- 接入点：chat 页新消息到达时 `announce("收到 N 条新消息")`；post 页列表加载完成 `announce("已加载 X 条微博")`、搜索完成 `announce("找到 X 条结果")`。
- announcer 的 CSS 类复用两页各自的 `.visually-hidden`？不行，shared 模块不依赖页面样式——在 announcer.js 里内联写入 style（position:absolute; width/height:1px; overflow:hidden; clip…），与 class 方案等价且自包含。

验证：Narrator / VoiceOver 走查：轮询到达新消息时只听到摘要，不听到整列表复读。

### 1.2 日期时间轴折叠头按钮化（post/dates.js）

问题：年/月折叠头是 `div` + click，键盘不可达、无 `aria-expanded`。

设计：

- `createYearGroup` / `createMonthGroup` 的 header 改为 `<button type="button">`，设 `aria-expanded="false"` 与 `aria-controls="<分组内容 id>"`；内容容器（`.year-months` / `.month-days`）加稳定 id（`months-2026`、`days-2026-09`）。
- `toggleGroup` 内同步 `aria-expanded`。
- post.css：`.year-header` / `.month-header` 补按钮复位（`border:0; background:transparent; width:100%; text-align:left; font: 原值`），`::before` 箭头与 padding 不动，视觉零变化。

验证：Tab 可达年/月头，Enter/Space 开合，屏幕阅读器报「已展开/已折叠」。

### 1.3 表情面板按钮化 + 焦点管理（chat/emoji-panel.js）

问题：表情格子是裸 `<img>`，键盘无法插入。

设计：

- 格子改 `<button type="button" class="emoji-cell">` 包 `<img>`；chat.css 的 `.emoji-cell` 调整为按钮复位 + 原尺寸（`padding:0; border:0; background:none; display:grid; place-items:center; width/height:32px`），`:hover` 不变。
- 打开面板时焦点移到第一个格子；关闭（外点 / Escape / 再点触发钮）后焦点还到 `#emoji-picker-open`。`attachDismiss` 不变，在 close 回调里做焦点归还。
- 网格内不加方向键漫游（Tab 原生可达即满足底线，漫游属增强，不在本批）。

验证：纯键盘：聚焦表情钮 → Enter 开面板 → Tab 选表情 → Enter 插入到光标处 → Escape 关闭焦点回原位。

### 1.4 附件区焦点框还原（chat/chat.css:901-903）

删除 `.composer-attachment:focus-visible { outline: none; }`，回归全局 3px 琥珀焦点框。视觉取舍：焦点框会出现在附件容器上，属正确反馈，不做替代样式。

### 1.5 prefers-reduced-motion 补全（chat.css / post.css）

现有媒体查询只停 `scroll-behavior`。补全为：

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    scroll-behavior: auto !important;
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}
```

- 覆盖 `.panel-state` 无限闪烁（WCAG 2.2.2）、`analysis-spin`、`size-flash`、庆祝相关 CSS 动画。
- 明确排除：celebration 的 canvas 帧动画与 WAAPI 位移由 JS 驱动，CSS 管不到——列入批次三收尾清单（`matchMedia("(prefers-reduced-motion: reduce)")` 命中时跳过 spawnCelebration，改为仅 announcer 通报），本批不动。

验证：DevTools → Rendering → Emulate prefers-reduced-motion：状态行不再闪烁，其余布局无变化。

### 1.6 回归庆祝 SR 通报（chat/celebration.js）

`spawnCelebration` 触发时调用 1.1 的 announcer：`announce("欢迎 {name} 回归")`。舞台本体加 `aria-hidden="true"`（`.celebration-stage` 是纯视觉表演，避免 canvas/button 被遍历到；舞台内的「跳过」按钮保留——它与 aria-hidden 冲突，故改为：舞台 aria-hidden，跳过按钮移到舞台外？）——简化决策：不做 aria-hidden，只加通报；跳过按钮本就是对键盘友好的逃生口，保留可达性更合理。

## 批次二：正确性收敛（前端为主 + CSP 一个后端点）

### 2.1 时区统一（post 页全链路 Asia/Shanghai，chat 仅查询类默认值）

设计：

- `shared/date.js` 新增：`SHANGHAI_OFFSET_MS = 8 * 3600 * 1000`；`epochToShanghai(epochMillis)` 返回 `{y, m, d, h, mi}`；`shanghaiDateValue()` 返回上海当天 `YYYY-MM-DD`；`formatDate` 改走上海时区换算。
- `search.js` 删除本地 `epochToDateStr`，改 import date.js 的等价函数。
- 默认值统一为上海当天：post 搜索弹窗的 `searchEnd`、同步历史弹窗 end、chat `history.js reset()` 的 `historyEnd` 与 `analysis.js resetForOpen()` 的 `analysisDate`，全部由 `localDateValue(new Date())` 换成 `shanghaiDateValue()`。
- 明确不动：chat 气泡上的消息时间（message-view 的 `formatTime`）保持浏览器本地显示——它只做展示、不与任何查询耦合；realtime 场景本地时间更符合直觉。该取舍写进 date.js 头注释。

取舍：若未来要做多时区，正确解是后端传时区或在 date.js 单点切换；本方案先把「两套并存可能差一天」的缺陷收敛为「一套口径」。

验证：系统时区切到 UTC-5，跨午夜博文在列表日期、时间轴日期、搜索跳转三者一致。

### 2.2 login 合并进 shared，统一 valid 语义

问题：chat/login.js 与 post/login.js 重复，且 `valid` 缺省语义相反（chat 缺省乐观 `!== false`，post 缺省悲观 `!result.valid`）。

设计：

- 新增 `shared/login.js`：`createLogin({elements: {loginExpired, loginQr, loginQrImg, qrLoading?}, idleText, loadingText, onRelogin?, onError})`，返回 `{showLoginExpired, checkLoginStatus, get qrPending()}`；内部组合现有 `createQrLogin`。
- 语义统一为严格 true：`result.valid === true` 视为有效，其余一律视为失效。取舍：接口异常时会误报「登录已失效」（可扫码恢复），好过漏报失效后空转轮询。
- chat/login.js 保留壳：周期性 `maybeCheck`（60 拍一次）是 chat 独有，包在 shared login 外；post/login.js 删除，post.js 直接装配 shared 版。

验证： mock `/weibo/login/status` 分别返回 `{valid:true}` / `{valid:false}` / `{}` / 500，两页行为一致（仅 true 隐藏过期提示）。

### 2.3 linkify 同源（shared/linkify.js）

问题：chat 链接化不剥尾随标点，post 有完整剥离逻辑（`URL_TRAILING_RE` + 括号配平）。

设计：

- 新增 `shared/linkify.js`：导出 `URL_TEXT_RE`、`stripUrlTrailing(url)`（post/posts.js:276-282 的现有逻辑平移）、以及 DOM 树版的 `linkifyUrls(root)` / `linkifyMentions(root)`（posts.js 现有实现平移）。
- chat/message-view.js 的 `appendMessageText`：保留其「先 URL 分段、段内再表情」的管线，URL 匹配改用 shared 的 `URL_TEXT_RE` + `stripUrlTrailing`（按剥离后长度截断分段）。
- post/posts.js 删除本地副本，改 import。

验证：消息「看 https://a.com/x, 这个」生成的 href 不含逗号；「wiki/A_(B)」右括号保留。

### 2.4 `toLocaleLowerCase("zh-CN")` → `toLowerCase()`

机械替换：groups.js:14-15、shared/highlight.js:15、search.js:119（含 `toLocaleLowerCase()` 无参处）。语义变化为零（中文无大小写折叠）。

### 2.5 posts 富文本清洗换 DOMPurify 白名单

问题：`sanitizeContentTree` 是黑名单移除，`data:` 链接、`form` 等在放行之列。

设计：

- `chat/dompurify.min.js` 移到 `shared/dompurify.min.js`；chat/analysis.js 的动态加载路径同步改。
- post/index.html 以 `<script src="../shared/dompurify.min.js" defer></script>` 常规加载（22 KB，列表渲染就要用，不做懒加载）。
- `renderContent` 管线改为：`DOMPurify.sanitize(html)` → `DOMParser` 解析 → `linkifyUrls` / `linkifyMentions`（2.3 的 shared 版）→ 链接补全 target/rel。`sanitizeContentTree` 整个删除。
- 注意点：linkify 在 sanitize 之后跑，新生成的 `<a>` 不再过 DOMPurify（自己创建、href 已校验非 javascript:，安全）；微博正文的 emoji `<img>` 与 `/n/` 链接在 DOMPurify 默认白名单内，无回归。

验证：构造含 `<script>`、`onerror`、`javascript:`、`data:text/html` 链接的 content 渲染全部被清；正常表情图、@提及、外部链接无回归。

### 2.6 CSP 响应头（后端一个点）

设计：

- 新增一个 `OncePerRequestFilter`（如 `SecurityHeadersFilter`），只对两个 app shell 的 HTML 响应加头：`/chat/index.html`（及 `/chat/`、`/chat`）、`/post/index.html`（及 `/post/`、`/post`）。明确排除 `/chat/dream/**`——`dream/1176117365.html` 含 2 个内联 `<script>`，严格 script-src 会废掉游戏页；API 与 `/chat/image` 代理不加（JSON/图片无需 CSP）。
- 策略：`default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: https:; media-src 'self' https:; connect-src 'self'; frame-src 'self'; font-src 'self' data:; object-src 'none'; base-uri 'none'; form-action 'self'`
  - `style-src 'unsafe-inline'` 必须保留：popover 定位、spacer 高度等都走 `element.style`。
  - `img-src https:` 必须保留：博主头像、微博表情直链外部 CDN。
- 验证：`curl -I` 两个 shell 页面带头、`/chat/dream/1176117365.html` 无头；两页 + 盗梦空间 + 群聊分析（marked/dompurify 动态加载）功能走查无控制台 CSP 报错。

### 2.7 小项归并

- `shared/fetch.js`：`fetchJson` 加第二参 `timeoutMs = 15000`，内部 `AbortSignal.timeout`；analysis 流式、同步历史等长请求不走 fetchJson 或显式传更大值（逐一核对调用点）。
- `shared/qr-login.js`：`refreshImage` 的 `preload.onerror` 补分支——loading 文案改「二维码加载失败，点击重试」并允许点击重拉，不再永远转圈。
- `post/viewer.js`：`img.onload/onerror` 加递增 token，旧图晚到的事件直接丢弃。

## 批次三：架构演进（前端为主，SSE 需后端立项）

### 3.1 消息数据上限（chat/sessions.js）

问题：`messages` Map 与 `heightByMid` 只增不减，长会话内存无界。

设计：

- 常量 `MAX_MESSAGES = 20000`、`TRIM_TO = 18000`。只在 `appendNewer` 末尾检查：超限时按 `orderedCache` 顺序删最旧 N 条，同步删 `heightByMid`、截断 `orderedCache` 头部，`windowStartIdx/windowEndIdx` 减去裁剪数并 clamp（为负则 `invalidateWindow()`）。
- 裁剪发生后 `hasMore = false; beforeCursor = null`：更早区间已被丢弃，继续向上翻页会把刚裁掉的消息拉回来，语义混乱；20k 条窗口内仍可自由滚动与恢复阅读位。history 弹窗走独立接口，不受影响。
- 读位恢复循环（`restoreReadingPosition` 的 while 补页）天然有 `beforeCursor` 空值早退，兼容。

验证：控制台模拟持续注入 2 万+ 条，`messages.size` 稳定在 18k-20k 区间，向上滚动与读位恢复功能正常。

### 3.2 轮询退避（chat/chat.js）

问题：固定 3 秒轮询，失败与 401 后仍全速打。

设计：

- `setInterval` 改 `setTimeout` 链：每轮结束后按 `delay = min(3000 * 2^failures, 30000)` 排下一轮，任一路径成功则 `failures = 0`。
- `groups.refreshGroups` / `sessions.refresh` 由吞错改为返回布尔（成功/失败），`refreshView` 汇总。
- 401 分支：任一 401 触发 `onAuthExpired` 后置 `authExpired = true`，此后 `refreshView` 只保留 `login.maybeCheck`，直到 `onRelogin` 成功复位。

验证：DevTools offline 模拟：请求间隔按 3s→6s→…→30s 退避，恢复在线后回到 3s；Network 面板无 401 后的持续打满。

### 3.3 群聊分析渲染节流（chat/analysis.js）

问题：流式渲染每 rAF 全文 `marked.parse` + `DOMPurify.sanitize` + `innerHTML`，长报告 O(n²)。

设计：`scheduleRender` 从 rAF 改 250ms `setTimeout` 尾帧节流（渲染仍合帧、仍跟随滚动到底）；`renderFrame` 改 `renderTimer`，`cancelOperation` 同步清理。增量渲染（按段落追加）列为后续增强，不在本批——先确认节流后流畅度可接受。

验证：5 万字报告流式输出，Performance 面板主线程长任务消失，滚动跟随正常。

### 3.4 SSE 消息推送（跨端立项，前端先行兼容）

背景：后端已有 SSE 能力（analysis 流式接口），消息增量推送是消掉轮询的正解。

设计（两阶段）：

- 阶段 A（后端新端点 + 前端并存）：`GET /chat/messages/stream?gid=`，新消息到达即推 `event: message`；前端 `EventSource` 收到后走现有 `appendNewer + 新消息提示` 管线。3 秒轮询保留为兜底，`EventSource` readyState 为 OPEN 时轮询降频到 30s 做心跳校齐；断线由 EventSource 自动重连，连续失败回落 3s 轮询（复用 3.2 退避）。
- 阶段 B（稳定后）：消息轮询下线；群列表轮询降频 30s（只为成员数/最新预览）；`markAway`/`catchUp` 的可见性补偿保留。
- 验收：消息端到端延迟 < 1s；Network 面板无 3 秒周期请求；断网 60s 恢复后无消息遗漏（catchUp 补偿生效）。

### 3.5 收尾清单

- 删除孤儿文件 `static/video-player.html`（全仓无引用，已核实）。
- 新增 `shared/storage-keys.js` 集中 localStorage/sessionStorage key（chat.js 2 个、attitudes.js 1 个、celebration.js 2 个、sessions.js 1 个前缀），防撞名。
- celebration 尊重 reduce 动效（见 1.5 排除项）：命中时跳过动画仅通报。
- post.css 四个同值字体令牌（`--serif/--hand/--hand-b/--mono`）补注释「刻意同值，差异在无雅黑平台的 fallback」，不精简（保留意图分层）。
- chat.css `.qr-loading[hidden]` 的 `!important` 改为与 `.login-expired:not([hidden])` 同套属性选择器写法，消掉全仓唯一的 `!important`。
