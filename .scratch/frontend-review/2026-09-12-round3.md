# Frontend Architecture Review · 第三轮（按用户三条原则的收口）

日期：2026-09-12　分支：`review/frontend-architecture`　前置：第二轮报告 `2026-09-12-round2.md`（提交 188bb5b）

用户在第二轮落地后提出三条原则，本轮据此收口：

1. **工具就是工具，要统一**
2. **模块要高内聚低耦合，内部细节不要外漏**
3. **代码可读性要统一，命名要规范要有迹可循，不必读内部细节也知道含义作用**

本轮同时纠正了第二轮报告 P2-3 的过早结论（「两页各自内部一致即可」）——composer.js 直接 import 而另外四个 chat 工厂靠注入，chat 页内部本就不一致；且这些注入缝从未被测试使用（Playwright mock 在 HTTP 层），属 YAGNI。

## 原则 1：工具统一（注入 → 直接 import）

无状态工具一律模块内 import，工厂参数只保留三类：元素句柄（`elements`）、实例句柄（`messageView` 等）、行为回调与配置。

| 工具 | 原送达方式 | 现在 |
| --- | --- | --- |
| `fetchJson` | chat 4 工厂注入 | 各工厂直接 `import`（`conversation-session` / `group-list` / `analysis` / `history`） |
| `compareMessages` / `captureScrollAnchor` / `restoreScrollAnchor` | 注入 3 工厂 | 直接 `import`（`conversation-session` / `history` / `celebration`） |
| `localDateValue` / `calendarMonthsAgo` | 注入 2 工厂 | 直接 `import`（`analysis` / `history`） |
| `MEDIA_TYPE`、`formatTime` / `formatDateTime` | chat.js 常量 + 函数注入 | 收编进 `chat-common.js` 导出，`message-view` / `history` 直接 import |
| `RED_PACKET_TEXT` | chat.js 常量注入 history | 归位 `history.js` 模块内常量（唯一消费者） |

保留的裸 `fetch` 例外（理由已在注释中）：`history.js` capture()（`/chat/since` 返回 204 无响应体）、`dream.js`（容错探测梦境页面存在性）。

装配根 `chat.js` 相应瘦身：不再 import 日期/锚点工具，不再持有 MEDIA_TYPE、红包文案与两个 Intl 格式化器，装配参数只表达「元素、实例、回调、配置」。

顺手删除的死 API（返回值无任何调用方）：`conversation.getCurrentGid`、`composer` 的整个返回对象（`createComposer` 改为裸调用）。

## 原则 2：内部细节不外漏（跨模块语言统一为领域值）

第二轮后仍残留的泄漏：dates 模块把 `.date-item` 元素交给调用方，导致 bloggers 读 `firstDay.dataset.date`、search 把元素回传给 `postsApi.activateDate`、posts 反向持有 `datesList` 清高亮——日期树的 DOM 约定（class、data 属性）泄漏给了三个模块。

本轮把「选中高亮」收归 dates（它才是日期树的属主），跨模块语言统一为**日期字符串**：

- `dates.selectFirstDate()` / `dates.revealDate(dateStr)` 返回 `YYYY-MM-DD` 字符串（找不到返回 null），内部完成展开与高亮；
- dates 点击日期项 → `onSelectDate(dateStr)` 返回是否被接受（posts 加载中拒绝），接受后才更新高亮，保证高亮与列表内容一致（原守卫语义不变）；
- `posts.selectDate(dateStr)` 只收日期字符串（守卫 + 加载）；`posts.activateDate` 删除，`selectedDate` 归位逻辑并入 `loadPosts`；
- search 跳转的滚动定位与闪烁收编为 `posts.revealPost(mblogId)`，search 不再知道 posts 卡片的 `#post-<id>` 命名约定；
- `posts` 不再接收 `datesList` 元素。

## 原则 3：命名有迹可循

- `datesApi` / `postsApi` → `dates` / `posts`：它们是页面内模块句柄而非 HTTP API，旧名误导；现在与 `messageView`、`groupList` 等实例句柄命名一致，`dates.loadDates()`、`posts.loadPosts()` 不读实现即可知含义。
- `epochToDateStr`（搜索跳转专用的时区日期换算）从 `helpers.js` 归位 `search.js`——单消费者逻辑不进共享工具；helpers.js 头部补注这条归位原则。
- 工厂参数形状统一为 `elements: {...}`：`message-view`、`dream` 从平铺元素参数改为与其他工厂一致的对象解构。

## 不做清单

- `window.WEIBO_EMOJI_MAP` 全局量：数据由脚本生成（`scripts/update-weibo-emoji.js`），改 ES module 导出需连带改生成器与断言该全局量的测试，收益不抵爆炸半径；两个消费者已统一走 `getWeiboEmojiMap` 惰性取值。
- `qr-login`（shared）的平铺参数：shared 库自有 API 风格，两处调用一致，不动。
- dream 对头像 `data-sender-id` 的读取：与 message-view 之间的稳定数据契约，非结构性 DOM 穿透。

## 验证

- 全部改动 JS 以真实 ESM `import` 复验解析（`node --check --experimental-detect-module` 对解构括号错位不敏感，本轮曾漏放 `analysis.js` 的一处签名闭合错误，被 `loads_chat_modules_after_dom_content_loaded_without_page_errors` 守卫测试与 ESM import 复验抓出）；
- `mvn test -Dtest="PostPageTest,GroupChatPageTest"` 103 例全绿（测试 mock 在 HTTP 层，注入改 import 不影响断言面）。
