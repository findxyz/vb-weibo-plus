# 历史微博同步提交即返回

日期：2026-10-25。

用户确认采用提交即返回方案，替换原先等待整个历史采集完成的交互。

- 选择博主和日期范围后提交，立即关闭弹窗。
- 服务端异步执行原有采集流程，提交接口返回 204，不返回采集计数。
- 提交成功提示“已提交后台同步，可继续浏览，稍后请手动刷新。”，提示 6 秒后隐藏。
- 前端不轮询、不持续显示加载、不自动刷新日期，也不显示“同步完成”。
- 进度、执行失败、完成情况和已有任务导致的跳过均通过服务端日志查看。
- 服务端原有历史采集锁、逐日分页、限速和幂等逻辑保持不变。
- 缺失参数、日期格式、非法 UID 和日期顺序在请求阶段校验；提交请求失败不自动重试。
- 后台 Credential 失效不会通过已返回的请求触发前端登录恢复，沿用页面登录检测与服务端日志。
- 当前任务不增加状态接口、进度存储、取消、重启续跑或任务队列。

验证边界：真实 Spring 异步代理下，阻塞采集不阻塞 HTTP 返回；接口参数和空响应；浏览器提交反馈、防重复提交、无轮询、手动刷新和提交错误；既有采集逻辑回归。

## 验证结果

- 新增真实异步代理测试，修改前 HTTP 被采集阻塞而失败，修改后立即返回 204 并通过。
- PostControllerTest、PostHistorySubmissionTest、PostServiceTest 共 41 项通过。
- 历史同步 10 项浏览器测试通过，另含组合操作、登录恢复和普通请求超时的整页回归。
- 类型检查、生产构建、差异格式检查通过；提交提示及最小窗口弹窗已人工检查截图。
- Standards 与 Spec 独立审查均无发现。
- mvn package 成功，325 项测试全部通过，已生成 weibo-plus.jar 和 weibo-plus.7z。
- 完整 post 页面回归为 140 项通过、1 项图片定位间歇失败，详见 issues/01-image-error-centering-flake.md。未认定与本次修改无关，也未修改图片定位逻辑。

本次保留“采集被阻塞时提交仍立即返回”的回归测试，直接约束提交与执行的边界，避免再次只通过延长前端等待时限处理长任务。
