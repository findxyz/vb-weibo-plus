# 03 — 建立流式微博媒体传输 seam

**What to build:** 让上层媒体模块能够携带当前 Credential 和调用方请求头流式读取微博媒体响应，同时保持现有图片媒体调用及错误语义不变，为大视频代理提供安全的传输 seam。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] 公共微博 HTTP 客户端提供专用于媒体的流式 GET 能力，不要求将响应完整转换为 `byte[]`。
- [ ] 流式能力允许调用方提供附加请求头，并向调用方暴露上游状态、必要响应头和响应流。
- [ ] 流式请求继续使用当前 Credential 和现有群媒体请求参数、固定请求头及 URI 构造规则。
- [ ] Credential 失效、限流重试、意外重定向和上游错误保持项目现有语义，日志不得泄露 Credential。
- [ ] 现有字符串请求和 `byte[]` 图片媒体请求保持行为兼容。
- [ ] 通过外部 HTTP seam 的逐个红绿循环证明响应可以分块消费、请求头能够传递、状态与响应头能够观察，并覆盖现有媒体回归行为。
- [ ] 不新增公开 Controller，不改变任何前端可见接口，也不修改 `API.http`。
- [ ] 相关单项测试和完整测试套件通过，完成 Standards 与 Spec 双轴代码审查后提交。
