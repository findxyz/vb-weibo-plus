# 04 — 通过本地代理打开群视频

**What to build:** 让群消息列表正确标识可播放视频并返回本地视频代理地址，使调用方能够通过现有群媒体接口流式打开完整视频，而不接触上游 URL 或 Credential。

**Blocked by:** 03 — 建立流式微博媒体传输 seam。

**Status:** ready-for-agent

- [ ] `mediaType = 10` 识别为视频；`mediaType = 13` 在符合现有红包判别规则时识别为红包，否则识别为视频。
- [ ] 视频存在封面引用时返回现有形式的 `previewUrl`；没有封面时返回空字符串，不生成视频首帧。
- [ ] 群消息响应增加 `videoUrl`；视频返回指向本地群媒体代理的相对 URL，非视频返回空字符串。
- [ ] 群媒体接口支持 `variant = video`，以 `200 OK` 流式返回完整视频及正确的媒体类型和内容长度。
- [ ] 视频请求验证 `gid`、`mid` 的归属关系和消息媒体类型；不得接受调用方提供的任意上游 URL。
- [ ] 图片 `preview`、图片 `original`、视频封面和既有错误响应保持兼容。
- [ ] 通过已确认的 Controller 与 Service / Mapper seam，以逐个红绿循环覆盖类型判别、封面降级、URL 契约、完整视频流和校验失败。
- [ ] `API.http` 增加查询含视频消息及通过 `variant = video` 打开完整视频的可直接执行示例。
- [ ] 相关单项测试和完整测试套件通过，完成 Standards 与 Spec 双轴代码审查后提交。
