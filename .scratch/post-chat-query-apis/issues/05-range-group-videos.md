# 05 — 支持群视频 HTTP Range

**What to build:** 让浏览器能够对本地群视频代理发起单个字节范围请求，并针对微博上游以 `200` 返回有效分片的行为，验证后规范化为标准的 `206` 响应。

**Blocked by:** 04 — 通过本地代理打开群视频。

**Status:** ready-for-agent

- [x] 支持封闭范围、开放结束范围和后缀范围形式的单个 `Range: bytes=...` 请求。
- [x] 有效范围返回 `206 Partial Content`、准确的 `Content-Range`、`Content-Length`、媒体类型和 `Accept-Ranges: bytes`，响应体只包含请求区间。
- [x] 不可满足的范围返回 `416 Range Not Satisfiable`，并包含 `Content-Range: bytes */<完整长度>`。
- [x] 格式错误和多范围请求返回 `400 Bad Request`，不请求上游媒体。
- [x] 上游以 `200` 返回有效分片时，在验证边界和 `Content-Length` 后向调用方规范化为 `206`；上游返回标准 `416` 时保持该语义，上游忽略或返回不一致分片时不得伪装成功。
- [x] 后缀范围先探测完整长度，再转换成显式范围请求，避免依赖上游的非标准后缀范围行为。
- [x] 无 Range 请求的 `200 OK` 完整视频行为和既有图片媒体行为保持不变。
- [x] `CHAT_API.http` 增加带 `Range` 请求头的可直接执行示例，并保留完整视频请求示例。
- [x] 相关单项测试和完整测试套件通过，完成 Standards 与 Spec 双轴代码审查后提交。
