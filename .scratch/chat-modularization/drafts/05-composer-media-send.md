# 05 — 编辑器与媒体发送独立管理

**What to build:** 用户继续通过编辑器发送文本、图片和视频，使用表情与粘贴附件；发送失败或消息已发出但同步失败时，页面保留既有内容和提示，发送结果归属于请求发起时的群。

**Blocked by:** 01 — 模块入口与共用消息展示。

**Status:** needs-info

## 实施边界

将编辑器 DOM、表情面板、附件校验和预览、发送锁、提示及内部事件收拢。入口只设置发送目标并接收成功回调。每次发送捕获群 ID 与文本或附件引用，不依赖后续变化的当前群。

不新增按群草稿，不取消已经提交的外部发送，不自动重试，不直接插入消息存储或主会话。发送后刷新通过入口按群协调。中文输入法误发作为后续问题，不混进本票结构迁移。

## Acceptance criteria

- [ ] Enter 发送与 Shift+Enter 换行、表情面板、插入位置和粘贴行为保持现有约定。
- [ ] 图片和视频的类型、大小校验、附件预览、移除和发送均正常。
- [ ] 文本与媒体共享模块内部发送锁，迁移不会因重复事件注册发出两次请求。
- [ ] 发送请求捕获起始群，切群后不能改变在途请求的群参数。
- [ ] 成功回调携带发送所属群，入口不会因为旧群发送完成改变新群的消息状态。
- [ ] 普通失败保留文本或附件，HTTP 409 继续显示已发送但同步失败并保留内容，不自动重发。
- [ ] 成功后的清理只由编辑器内部执行，不由会话模块操作输入框。
- [ ] 替换或删除附件释放对应 Object URL，原有图片和视频输入可再次选择。
- [ ] 没有后端协议、上传链路、存储规则或第三方依赖变更。
- [ ] 旧入口不再保留发送锁、附件引用、发送函数或编辑器事件。

## 验证方法

使用模拟发送接口验证文本、图片、视频请求与响应，覆盖成功、失败和 HTTP 409。延迟旧群发送响应后切换群，检查请求归属和新群页面。验证成功后读取本地消息接口，不出现前端乐观插入。

## 提交与回滚

编辑器与所有调用入口一起迁移。若修正了旧群完成回调影响新群的行为，先补失败测试，再单独提交修复。回滚不得清空用户已有草稿或持久化数据。

## Comments

草案待评审。附件在发送期间被用户替换或移除的更完整交互策略若需改变，先记录为额外需求，不扩大本票。
