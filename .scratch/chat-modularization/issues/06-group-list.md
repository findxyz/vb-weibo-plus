# 06 — 群列表与元数据独立管理

**What to build:** 用户能够加载、搜索、选择群聊，在初始失败后重试；后台 View Refresh 更新群摘要与数量时，当前会话保持阅读位置，且仍可恢复上次选中的群。

**Blocked by:** 01 — 模块入口与共用消息展示。

**Status:** resolved

## 实施边界

群列表模块拥有列表数据、搜索、渲染、比较和请求锁。入口保留当前群选择、最后选群持久化和初始化策略。模块通过选择及元数据变化回调提供只读快照，入口更新当前群标题，不直接访问内部数组。

初始加载和定时刷新共享内部请求去重，避免相互覆盖；模块自身不创建轮询器，不触发后台采集。不新增群删除后的自动跳转策略。

## Acceptance criteria

- [x] 初始成功、空列表、加载失败及重试路径保持可用。
- [x] 搜索过滤、摘要和群数量展示保持一致。
- [x] 用户点击群只产生一次选择回调；程序更新选中样式不会再触发选择。
- [x] 上次选择恢复由入口完成，模块返回的数据足以处理保存群不存在的回退。
- [x] 元数据刷新更新当前群信息而不重新加载首屏、清空消息或重置滚动。
- [x] 初始请求与周期刷新不会创建互相覆盖的并发加载。
- [x] 对外群数组和管理员数组不暴露内部可变容器。
- [x] View Refresh 只访问本地群查询，不调用远程群采集。
- [x] 旧入口不再保留列表渲染、搜索事件和群行点击处理。

## 验证方法

运行现有搜索、恢复选群、初始失败和摘要刷新测试。使用延迟群列表响应验证初始化与刷新重叠，使用变化的群元数据验证主消息 DOM 和滚动未被清空。

## 提交与回滚

列表渲染、请求和选择回调作为一个完整迁移增量。回滚不修改最后选群的持久化键，保持原保存值可读取。
