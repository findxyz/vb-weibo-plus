# 04 — 回归庆祝独立管理

**What to build:** 用户能够为当前群成员设置 Return Celebration 名单和间隔，符合现有条件的新消息触发动画；首屏只建立基线，切群或跳过后旧动画不继续出现。

**Blocked by:** 01 — 模块入口与共用消息展示。

**Status:** resolved

## 实施边界

庆祝模块拥有名单、已见时间、配置浮层、素材缓存、活动动画及资源清理。主会话通过入口按首屏、历史和新消息三种来源通知它；它不读取或修改主会话 Map。新增名单成员通过只读消息快照建立基线。

保留动画外观、时间线、持久化键和值结构，不引入新动画框架或队列。切群关闭旧配置浮层作为独立修复提交。

## Acceptance criteria

- [x] 姓名入口和名单入口都能打开同一份成员配置，修改间隔、加入与移除行为保持一致。
- [x] 现有持久化名单和已见时间无需迁移即可读取，刷新页面后仍有效。
- [x] 首屏和上翻消息只建立或提高基线，不追溯触发动画。
- [x] 没有可靠前序时间时先建立基线，后续消息按现有间隔规则判定。
- [x] 一次刷新中多条符合条件的新消息继续按现有规则处理。
- [x] 切群或手动跳过后，动画、延时与晚到图集加载不会重新显示旧群庆祝。
- [x] 切群后旧成员配置浮层关闭，不能继续把旧群配置当成新群成员编辑。
- [x] 主会话只提供消息来源回调和快照，庆祝模块不接收全局状态对象。
- [x] 素材失败时保持现有降级行为，不阻断消息刷新。
- [x] 原入口不再保存庆祝名单、浮层草稿或动画状态。

## 验证方法

运行现有首屏、基线、多消息和切群取消测试，增加浮层打开时切群以及图集尚未完成时切群的验证。通过页面元素和持久化结果断言，不依赖动画内部变量。

## 提交与回滚

完整庆祝路径一次迁移，旧浮层清理单独修复。回滚时保留用户持久化数据，不删除或重置名单。
