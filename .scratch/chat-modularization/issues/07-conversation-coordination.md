# 07 — 当前会话与页面协调收口

**What to build:** 用户在独立的当前会话中浏览最新消息、上翻旧消息、暂停和恢复跟随，并在页面返回时完成 Catch-up；快速切群或请求失败时，新群标题下不再残留上一群消息。页面入口只协调已经提取的功能。

**Blocked by:** 02 — 群聊分析独立会话；03 — 历史浏览与历史采集独立会话；04 — 回归庆祝独立管理；05 — 编辑器与媒体发送独立管理；06 — 群列表与元数据独立管理。

**Status:** in-progress

## 实施边界

收拢主会话 Map、游标、请求代次、渲染增量、跟随、消息区事件和观察器。入口仅保留当前群、模块组装、登录、初始化、页面可见性及刷新调度。分别通过首屏、历史、新消息回调连接庆祝，通过带群归属的成功回调连接编辑器。

每次切群同步建立新代次和清空旧消息 DOM，再异步加载首屏。快速切回同一 gid 仍视为新代次。相关修复和机械迁移分开提交。普通刷新缺口、首屏失败后分页恢复等已知问题另行修复。

## Acceptance criteria

- [ ] 当前会话独占 Map、游标、跟随状态和消息 DOM，入口不直接操作它们。
- [ ] 上翻分页、媒体加载、增量 DOM 复用、新消息按钮和跟随提示保持既有正常行为。
- [ ] 页面隐藏后暂停跟随，回来执行本地 Catch-up，保持阅读位置并提示新消息。
- [ ] 群切换时立即清空旧消息 DOM；新群为空或加载失败时也不能显示旧群消息。
- [ ] A → B → A 的旧请求和旧媒体回调无法更改当前代次的消息或滚动。
- [ ] 首屏和上翻只发基线回调，刷新和追平的新消息发到达回调，均携带所属群。
- [ ] 旧群发送完成不会推动当前新群会话跟随或加载旧群消息。
- [ ] 入口在切群时同步更新各模块归属，并处理弹窗和庆祝旧浮层的生命周期。
- [ ] 元数据更新走轻量更新，不调用会话重新打开。
- [ ] 重新扫码初始化复用现有模块，不增加事件、轮询器或 MutationObserver。
- [ ] 删除原共享状态和已经迁移的事件副本，功能模块没有反向导入入口。
- [ ] 群聊 UI 定向回归和新增切群失败测试通过。

## 验证方法

用可控延迟构造快速切群、空群、首屏失败和旧图片晚加载，通过标题、消息内容和滚动断言。先用失败测试证明旧 DOM 残留，再修复。检查隐藏与返回时的请求方向和游标，确认仍是本地 View Refresh。

## 提交与回滚

可以在本票内分成会话提取、入口连接清理、跨群生命周期修复三个连续提交，但每个提交均保持可运行。回滚修复不得恢复另一套未调用的共享状态；回滚提取时同时恢复入口连接。
