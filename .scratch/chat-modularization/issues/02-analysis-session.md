# 02 — 群聊分析独立会话

**What to build:** 用户能够打开当前群的 Analysis、查询历史报告、查看详情、生成流式结果和下载报告；关闭后重新打开时，旧群或旧操作的返回内容不会覆盖当前页面。

**Blocked by:** 01 — 模块入口与共用消息展示。

**Status:** resolved

## 实施边界

把 Analysis 的 DOM、列表与详情状态、SSE 解析、Markdown 渲染、报告下载和所有内部事件整体迁入独立模块。入口只负责打开和关闭。采用独立的弹窗会话版本和视图操作版本，避免查询列表误伤有效生成流程。

机械迁移先保持现有正常路径。随后用独立修复提交落实设计中的操作隔离：开始生成时使旧视图请求失效，生成期间禁用返回入口，关闭仍可用；完成时使用终态报告展示，返回列表才刷新列表。客户端停止读取不代表后端停止生成，不新增取消端点。

## Acceptance criteria

- [x] 打开时使用所选群快照，列表分页、详情元数据、提示词复制及 Markdown 下载保持可用。
- [x] 分析模块独占状态和 DOM，入口不读取当前报告、分页或生成状态。
- [x] SSE 数据跨网络分块时仍正确累积并展示，done 事件报告接管最终展示。
- [x] 先以失败测试证明旧详情响应或旧生成回调会污染新弹窗，再修复。
- [x] 关闭、重开、快速详情导航后，旧成功、失败和 finally 回调均不得更新新操作的 DOM 或按钮。
- [x] 新生成使旧列表和详情读取失效，生成过程中不能返回列表触发视图竞争，关闭按钮仍可用。
- [x] 待渲染帧在操作失效或最终报告接管时取消，不能覆盖最终报告。
- [x] 关闭时释放客户端流读取资源；再次打开可以发起新的分析操作。
- [x] 下载内容和文件名属于当前展示报告，开始新会话时不能下载上次报告。
- [x] 不增加后端请求协议、保存机制、前端库或未经评审的安全降级行为。

## 验证方法

使用本地模拟接口构造延迟详情、分段 SSE、error 事件和关闭后晚到响应，通过弹窗正文、按钮状态和下载内容断言。覆盖先打开一份报告，再生成另一份的路径。既有成功路径和新增竞态测试一起运行。

## 提交与回滚

提取提交与生命周期修复提交分开。回滚修复时可保留模块结构；若回滚整个提取，恢复入口连接及旧事件绑定，避免两套分析处理器并存。
