# 01 — 模块入口与共用消息展示

**What to build:** 用户从原群聊页面进入后，页面通过原生模块脚本启动，主会话和历史上下文继续完整显示文本、表情、头像、管理员样式、微博卡片和媒体。完成实际展示路径的模块迁移，为后续功能提取提供可运行基础。

**Blocked by:** None — can start immediately.

**Status:** resolved

## 实施边界

先保留尚未提取的功能闭包，迁出实际复用的日期、消息比较、滚动锚点以及消息展示。展示函数通过参数获得管理员身份、目标高亮和成员点击行为，不再读取当前群或直接调用庆祝功能。原图查看器初始化一次。

模块导入不绑定事件或请求数据；初始化等待页面和原有第三方依赖就绪。保留静态部署方式，不引入构建工具、前端依赖管理或后端修改。单个调用方的函数不放进公共模块。

## Acceptance criteria

- [x] 原页面 URL、DOM 标识、CSS 和素材路径保持不变，全部模块响应成功且 MIME 可供浏览器执行。
- [x] 主会话和历史上下文共享消息展示行为，历史结果列表仍使用轻量摘要，不额外加载媒体。
- [x] 文本链接、表情、微博卡片、系统消息、管理员样式、附件下载、原图和视频播放保持可用。
- [x] 只有主会话姓名触发庆祝配置，历史姓名仍为普通文字。
- [x] 共用渲染模块不读取当前群列表、消息 Map 或庆祝状态。
- [x] 滚动锚点函数显式接收容器，历史与主会话使用各自容器。
- [x] 重复初始化业务数据不重复绑定原图查看器事件。
- [x] 删除迁出的旧函数副本，其他功能暂保持原结构且能够运行。
- [x] 定向浏览器回归通过，无 pageerror、模块加载错误或第三方依赖初始化错误。

## 验证方法

先运行既有群聊页面测试建立基线，再迁移并重跑。增加资源加载和启动检查，覆盖直接刷新页面及缓存命中的媒体预览。通过实际展示断言验证，不测试文件行数，也不将内部函数暴露到 window。

## 提交与回滚

入口脚本类型、真实消息展示提取和对应测试构成一个可回滚增量。回滚必须同时恢复入口加载方式和调用方，避免保留引用不存在模块的页面。
