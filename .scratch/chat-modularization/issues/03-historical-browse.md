# 03 — 历史浏览与历史采集独立会话

**What to build:** 用户在独立的 Historical Browse 中按日期、发送者和关键词检索本地消息，查看目标上下文并双向翻页，也能启动 Historical Capture；这些操作不改变主会话的消息、滚动和跟随状态。

**Blocked by:** 01 — 模块入口与共用消息展示。

**Status:** resolved

## 实施边界

将筛选、分页、上下文、滚动锚点、采集提示和弹窗内部事件整体迁入历史模块。打开时捕获群与管理员信息，关闭后旧响应失效。入口只打开或关闭，不持有历史游标和筛选条件。

采集仍是现有异步启动协议，返回提示只表示请求已接受；不增加进度查询、自动远程采集或对主消息流的写入。采集提示的会话隔离采用独立修复提交。

## Acceptance criteria

- [x] 每次打开按现有规则重置日期、关键词、发送者和历史上下文。
- [x] 日期筛选、大小写高亮、无结果、查询错误和分页显示保持一致。
- [x] 点击结果可定位目标消息，向前和向后加载使用自己的游标。
- [x] 加载更早消息保持锚点，单次下滚不会意外连续吞入多页。
- [x] 历史消息展示使用打开时的群信息，不依赖主会话可变状态。
- [x] 旧查询、旧上下文响应无法覆盖较新的查询或重新打开的弹窗。
- [x] 采集提示使用会话版本约束，延迟响应不能污染重新打开的弹窗。
- [x] 关闭弹窗不宣称取消已经提交的 Historical Capture，重新查询可看到采集结果。
- [x] 主会话消息 Map、滚动位置和跟随状态不被历史操作改变。
- [x] 迁出的函数、状态和事件在旧入口中没有副本。

## 验证方法

重用既有筛选、上下文、锚点和过期查询浏览器测试，增加采集请求晚到与关闭重开的路径。通过模拟本地查询与采集接口检查参数，确认浏览历史不触发远程采集，只有用户点击采集才发送对应请求。

## 提交与回滚

完整历史路径作为提取提交，采集提示失效作为独立修复提交。回滚时一并恢复历史按钮与内部事件的所有权，保持同一事件只有一个处理器。
