# 02 - Historical Capture 边界打磨

**What to build:** 在切片 01 端到端打通的基础上，把边界情况打磨到可交付状态：空群首次同步、并发锁冲突下的行为、以及按钮的状态/提示文案，确保操作者在任何情况下都能得到合理的反馈，不会误以为「同步正在进行」而实际什么都没发生。

**Blocked by:** 01 - Historical Capture 端到端打通

**Status:** ready-for-agent

- [ ] 空群验证：对一个本地无任何消息的群触发同步，确认 `beforeMid=null` 走「拉最新 50 条」语义后能正常向旧翻页入库，不报错、不卡死
- [ ] 锁冲突行为确认：当 `saveBySinceLock.tryLock()` 失败（与并发 Historical Capture 撞锁）时，端点仍返回 200，明确记录日志以便排查；确认与 `saveIncremental`（定时任务，不持此锁）不互斥
- [ ] 按钮状态：点击「同步历史」后按钮置灰，防止重复点击触发多次锁冲突；异步端点返回后恢复或保持提示，由后端实际完成与否决定（fire-and-forget 下前端无法感知完成，按提示文案处理）
- [ ] 提示文案：空提交（未选时间点）、网络异常、已提交三种状态都有清晰的中文提示，遵循 AGENTS.md 的中文标点与中英文间距规范
- [ ] 验证：空群触发同步后能拉到消息；连续快速点击两次按钮，第二次得到合理提示而非静默成功
